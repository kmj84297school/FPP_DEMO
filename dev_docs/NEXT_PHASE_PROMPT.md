## 프롬프트 (여기서부터 복사)

너는 FPP(Football Player Potential AI) 프로젝트의 3단계를 맡는다. 먼저 저장소 루트의
`CLAUDE.md`를 끝까지 읽어라. 거기 적힌 **"정직한 측정" 원칙은 이 프롬프트의 모든 지시보다
우선한다.** 아래 요청 중 그 원칙과 충돌하는 것이 있으면 요청을 따르지 말고 충돌을 보고해라.

### 0. 이 프롬프트를 읽는 방식

- 나는 "모든 문제를 뿌리부터 뽑아달라"고 요청한다. 그러나 문제마다 뿌리의 깊이가 다르다.
  아래 §2에 문제를 **A(지금 데이터로 해결 가능) / B(새 데이터가 있어야 해결) / C(원리상 불가)**
  로 분류해뒀다. A는 실제로 뽑고, B는 뽑기 위해 무엇이 필요한지 정확히 명세하고, C는
  왜 불가능한지 한 문장으로 확인만 해라. **B·C를 A처럼 해결한 척하는 것이 이 프로젝트에서
  가장 나쁜 결과다.**
- 모든 모델링 변경은 **GroupKFold(선수 단위) 5겹 폴드 밖 지표**로 전후 비교하고, 그 표를
  커밋 메시지와 `CLAUDE.md §5`에 남겨라. 지표가 나빠지면 채택하지 마라. "보기 좋아졌다"는
  채택 사유가 아니다.
- 단계마다 작동하는 상태로 `main`에 배포하고 멈춰서 보고해라. 한 번에 다 바꾸고 끝에 보고하지 마라.
- 이전 세션이 이미 배제한 가설은 재조사하지 마라 (§1 참조). 시간 낭비다.

### 1. 현재 상태 (2026-08 기준, 전부 실측)

**아키텍처**: GitHub Pages 정적 사이트. `build/01~13` 파이썬 파이프라인이 빌드 타임에
전부 계산해 `docs/data/*.json`으로 굽고, `docs/assets/*.js`가 읽어 렌더링. 서버·크롤링 없음.
설정은 `build/lib/config.py` 단일 출처.

**데이터**: `data/fpp_features_clean_2018_2025.csv` 19,783행 × 169열, 빅5 리그 필드플레이어,
2018~2025 전 시즌 연속. 2024·2025는 서로 다른 형태의 Kaggle 소스에서 반입
(`build/12`, `build/13`). 2025-26은 공개본에 고급지표 블록이 없어 미반입.

**모델** (전부 `build/07_train_models.py`, GroupKFold 5겹):

| | 성장기(U23) | 성숙기(24~38세) |
|---|---|---|
| 잔존 분류 AUC | 0.693 ± 0.032 | 0.732 ± 0.013 |
| 2~3년 후 능력 MAE / R² | 6.00 / 0.306 | 5.31 / 0.500 |
| 80%/50% 구간 실측 커버리지 | 82.6% / 52.2% | 83.2% / 53.2% |
| 코호트(라벨) | 2,268 (1,638) | 5,214 (2,799) |

회귀 타깃은 **Δ = 미래능력 − 현재능력**(레벨 아님). 코호트는 2018~2022(t+2·t+3 모두 관측
가능한 해만). 신뢰구간 = `mu ± z·sqrt(σ_model² + σ_residual²)`.

**사이트**: 검색 1,692명 / 예측 1,455명 / 검증범위 밖 경고 19명. 선수 상세페이지에 이중렌즈
분해, 5그룹 레이더, 강점/약점, 스타일 판별근거, 포지션 레이더, 정성 시그널(규율·가용성·꾸준함),
2~3년 후 예측+구간, 유사선수 10명(실제 결과 포함), 자동 서술문, 코칭 제안, 로드맵.

**이미 배제된 가설 — 재조사 금지**:
- "라벨과 현재 점수의 스케일이 다르다" → 아님. 동일 산식, U23 코호트 실제로 53.3→53.8 상승.
- "모델이 과도하게 수축한다" → 아님. OOF 보정 기울기 0.870/0.926(<1), 선형 보정 시 MAE 불변.
- "코호트를 늘리면 상위권 라벨이 생긴다" → 아님. 2018~2023 어느 해도 85점+ 라벨 0명.
- "위키피디아 정성점수를 되살리자" → 하지 마라. 인계문서에 편향 결함으로 기록됨.

### 2. 문제 목록과 뿌리 진단

#### A. 지금 데이터로 해결 가능 — 실제로 뽑아라

**A1. 포지션이 세 종류뿐이다 (가장 깊은 뿌리).**
`pos_primary`가 FW/MF/DF만 있다. 풀백과 센터백이 같은 "DF" 풀에서 백분위를 받고,
수비형 미드필더와 공격형 미드필더가 같은 "MF" 풀에 있다. 인계문서 §D의
"수비수 팀 강도 편향", "포지션 간 분산 불일치(FW sd 13.8 vs DF 7.5)", 그리고 스타일 렌즈가
애초에 필요했던 이유("공격형 풀백 저평가")의 상당 부분이 여기서 나온다.
- 원본 `Pos` 컬럼에는 "DF,MF" 같은 복합 표기만 있고 FB/CB/DM/AM 구분은 없다.
- 해결 방향: 구성비(shape) 피처로 **역할(role)을 데이터에서 추론**해 6~8개 세부 포지션
  (CB/FB/DM/CM/AM/W/ST 등)을 만들고, 백분위 풀과 포지션 렌즈 가중치를 그 단위로 재설계.
  단, 인계문서 §4-3 "스타일 판별은 구성비로, 점수 가중과 분리" 원칙(순환성 방지)을 지켜라.
- 검증: 재설계 후 세부 포지션 간 능력점수 분산이 균질해지는지, 그리고 예측 MAE가
  나빠지지 않는지. 둘 다 표로.

**A2. 상위권 외삽 — 반쯤 해결됨, 나머지 반.**
Δ 타깃으로 구조적 천장은 제거했지만, Δ 모델은 학습 범위 밖에서 "변화 없음"으로
수렴하는 낙관 편향이 있다(현재 19명에게 경고). 후보 두 가지를 **둘 다** 시험해 표로 비교:
- 라벨을 t+2·t+3 **평균 대신 최댓값**으로 ("잠재력"의 정의에 더 가깝고 상단 압축 1.5점 해소)
- **분위수 회귀**(XGBoost `reg:quantileerror`, q=0.1/0.5/0.9)로 구간을 직접 추정.
  현재 정규분포 가정(z·σ) 대신 비대칭 구간이 나오면 상위권에 더 정직하다.
채택 기준은 폴드 밖 커버리지와 상위 구간(현재능력 75+) MAE.

**A3. 하이퍼파라미터가 한 번도 튜닝되지 않았다.**
`HANDOVER_DETAIL.md`에 "튜닝 미수행, 보수적 기본값"으로 기록돼 있다. GroupKFold 안에서
탐색하되(누수 주의) 과적합 방지를 위해 탐색 공간은 작게. 개선폭이 작아도 "시도했고 이만큼"을
기록하는 것 자체가 가치다.

**A4. 잔존 분류가 약하다 (U23 AUC 0.693).**
"빅5 이탈"이 "기량 하락"과 "챔피언십·에레디비시로 이적해 잘 뛰는 것"을 구분 못 한다.
데이터 안에서 할 수 있는 것: 이탈 직전 시즌의 출전시간 추세, 나이, 클럽 규모 대리변수
(팀의 리그 순위·득실)를 피처로 추가. 데이터 밖(B4)이 진짜 해결이지만 이것부터.

**A5. 설명 가능성 없음.**
왜 이 선수가 이 예측을 받았는지 사이트가 말해주지 않는다. SHAP(TreeExplainer)으로
선수별 상위 5 기여 피처를 빌드 타임에 계산해 JSON에 넣고 상세페이지에 표시.
"성장궤적(d_grp_progress)이 +2.1 기여" 같은 식으로. 자동 서술문도 이걸 근거로 다시 써라.

**A6. 능력점수 v2 진단 항목 (인계문서 §D).**
박스 포처 저평가(그룹 내 균등가중), 수비수 팀 강도 편향, 포지션 간 분산 불일치.
A1을 먼저 하면 절반은 같이 풀린다. 남는 것을 진단→처방→검증.

**A7. 합성 ID 981명 (2025 스냅샷의 39%).**
2024·2025 반입 시 기존 데이터에 없던 선수는 `n24*/n25*` 합성 id를 받았다. 이들은
사진이 없고, 2024↔2025 사이는 연결됐지만 2023 이전과는 끊겨 있다. 지금 데이터로 할 수
있는 것: (이름, 생년, 국적, 포지션)을 함께 쓴 더 강한 매칭으로 기존 id 복구율을 높이되,
**동명이인 오결합은 단 한 건도 허용하지 마라** — 복구 건마다 근거를 로그로 남겨라.
진짜 해결(실제 fbref_id 확보)은 B1.

**A8. 인터페이스 — "정말 퀄리티 좋게".**
현재 사이트는 기능은 다 있지만 "세로로 긴 한 페이지"다. 다음을 구현하되, 디자인 시스템
(다크 테마, `#0b0c10`/`#11151b`/`#e9eef5`/`#19ffa7`/`#ffd700`)은 유지:
- **선수 비교**: 두 선수를 나란히 놓고 레이더 겹치기, 지표별 차이 강조.
- **필터**: 리그·포지션(A1의 세부 포지션)·나이대·스타일·예측 대상 여부. URL에 상태 저장
  (permalink). 지금은 검색어조차 URL에 안 남는다.
- **예측 설명 패널**: A5의 SHAP 기여도를 시각화. 이것이 이 사이트의 핵심 차별점이 돼야 한다.
- **모바일**: 실제로 375px 폭에서 열어 스크린샷을 찍고 깨진 곳을 고쳐라. 테이블은 카드로.
- **성능**: `docs/data/index.json`이 1,692명 × 12필드다. 첫 로드 크기를 측정하고, 200KB를
  넘으면 필드를 줄이거나 분할해라.
- **접근성**: 색만으로 정보를 전달하는 곳(배지 색상)에 텍스트/아이콘을 병기.
- **아바타**: 합성 id 선수의 이니셜 폴백을 더 보기 좋게. 사진 있는 선수와 시각적 위계가
  어긋나지 않게.
- 스크린샷으로 전후를 보여라. "고쳤다"는 말 대신.

#### B. 새 데이터가 있어야 해결 — 무엇이 필요한지 정확히 명세하라

**B1. 실제 fbref_id.** 합성 id의 근본 해결. 필요한 것: FBref 선수 URL이 포함된 데이터셋,
또는 (이름, 생년, 국적)→fbref_id 매핑 테이블. 어떤 공개 소스에 있는지 조사해 소유자에게
다운로드를 요청하는 명세를 써라(이 환경은 Kaggle·FBref 직접 접속이 막혀 있다. GitHub raw는 됨).

**B2. 외부 검증 라벨 — 가장 중요한 과학적 비판에 대한 답.**
현재 "능력점수로 능력점수를 예측"한다(라벨 순환성). 시장가치(Transfermarkt), 이적료,
국가대표 발탁, 개인 수상 같은 **외부 지표**와 능력점수·예측치의 상관을 보여야 이 점수가
"진짜 무언가"를 측정한다고 말할 수 있다. 어떤 데이터가 어떤 형태로 필요한지 명세하고,
소유자가 구해오면 바로 돌릴 수 있는 검증 스크립트를 미리 작성해라.

**B3. 부상 기록.** 정성 시그널의 "가용성"은 출전시간 점유율 대리변수다. 실제 부상 이력이
있으면 로테이션과 부상을 구분할 수 있다. 필요한 데이터 명세.

**B4. 빅5 밖 리그.** "이탈" 라벨의 근본 해결. 2부 리그·기타 1부 리그 데이터가 있으면
이탈을 "하락"과 "수평 이동"으로 나눌 수 있다. 명세.

**B5. 2025-26 고급지표.** 현재 공개본은 표준 스탯만 있다. 어느 소스에 포제션·수비·GCA
블록이 있는지 조사.

**B6. GK 모델.** `data/fpp_features_GK_2018_2023.csv`가 있지만 2024·2025 GK는 반입 시
버렸다. GK 전용 스코어링·모델은 필드플레이어와 완전히 다른 설계가 필요하다. 착수 전
소유자와 상의(인계문서 §D).

#### C. 원리상 해결 불가 — 확인만

**C1. 상업적 사용.** 데이터 라이선스(FBref/Opta 유래)상 불가. BYOD 또는 정식 라이선스
전제. 코드로 풀 수 있는 문제가 아니다. 인계문서 §7 그대로.

### 3. 작업 순서 (권장)

1. A1 포지션 세분화 → 이것이 다른 여러 문제의 상류다. 먼저 해라.
2. A5 SHAP → A8 예측 설명 패널. 사이트의 핵심 차별점.
3. A2 상위권 외삽 후보 비교.
4. A3 튜닝 + A4 잔존 피처.
5. A8 나머지 인터페이스.
6. A7 id 복구.
7. B 항목 전부: 조사 + 명세 문서 `dev_docs/DATA_REQUESTS.md` 작성.

각 단계 끝에: 배포, 전후 지표 표, 스크린샷, `CLAUDE.md` 갱신, 보고. 그 다음 단계로.

### 4. 절대 규칙

- 폴드 밖 지표가 나빠지는 변경은 채택 금지. 표로 보여라.
- 없는 수치를 만들지 마라. 측정 못 하는 것은 "측정 안 함"이라고 써라.
- 이름으로 선수를 조인하지 마라. 동명이인 33명 확인됨. (이름, 생년) 이상만.
- 크롤링·실시간 외부 호출 금지. 정적 사이트 원칙.
- `scoring_v1.py`, `boot_ci.py`는 원본 보존. 바꿔야 하면 v2 파일을 만들고 전후 비교.
- 커밋 메시지는 "무엇을"이 아니라 "왜"를 써라. 이전 커밋들을 참고.
- 확신 없으면 멈추고 물어라. 특히 §4 "핵심 설계 결정" 8개 항목을 건드릴 때.
